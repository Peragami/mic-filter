# 目標の音（2026-11-08 たくみさんの希望を仕様化）

希望：ノイズがなくクリア。古い安物マイクでも高音質マイクみたいな音。補間もしてほしい。

## 「いいマイクの音」の定義（このアプリでの答え、2026-11-08 たくみさん合意）
測定上の良さ（フラットな特性、低ノイズ、低歪み、広いダイナミックレンジ）と、人が「いい音」と感じるものは別。
配信・通話で人がいい音と呼ぶのは大抵「放送の声」：近くで録った乾いた音、言葉がはっきり、音量が安定、余計な音が無い。
つまり狙うのは忠実さそのものではなく **「その人らしく、はっきり、近くに聴こえて、邪魔な音が何も無い」** こと。
逆説として、良いマイクは部屋の反響やノイズまで忠実に拾うので、未処理の部屋では安いマイク＋近接＋処理の方が「良く」聴こえることもある。音の半分はマイクではなく距離・部屋・処理で決まる。

## 「高音質マイクっぽさ」の正体（分解すると作れる）
安物マイクが安く聴こえる原因は、ほぼこの6つ。逆に全部潰せばかなり高く聴こえる。
1. **ノイズが多い**：サーという自己ノイズ、ファン、ハム音
2. **周波数が偏ってる**：低音が薄い／高音が無い（こもる）／中音に変なピーク（箱っぽい、キンキン）
3. **音量がバラバラ**：小さい声と大きい声の差、距離で変わる
4. **余計な音**：リップノイズ、破裂音、サ行の刺さり、部屋の反響
5. **帯域が狭い**：上（10kHz〜）が切れてて「空気感」がない、下も薄い
6. **歪み・割れ**：入力過大でクリップした部分

## 対応チェーン（v2案、順序つき）
```
入力 → デクリップ（割れた波形を補間で修復）
     → ハイパス＋ハムノッチ
     → ノイズ除去（RNNoise：喋ってる間も消す担当。下記モード参照）
     → デクリック／リップ除去（見越し128）
     → 補正EQ（マイクの偏りをフラット＋声の芯 2〜5kHz を少し）
     → ディエッサー（動的EQ）
     → コンプ（音量を揃える＝プロっぽさの大きい部分）
     → 帯域拡張（下記「補間」の2方式）
     → リミッター → 出力
```
＋ **自動キャリブレーション**（リアルタイム外でOK）：数秒しゃべってもらい、長期スペクトルを「良い声の目標カーブ」と比較して補正EQを自動生成、マイク個体差（ヘッドセット／ノートPC内蔵／古いUSB等プリセット）にも対応。これが「安物を高く聴かせる」一番の効きどころになりうる。

## 「補間」について — 3種類ある、効果が違う
| 種類 | 中身 | 効くか |
|---|---|---|
| 欠けた波形の補間 | クリック部分／クリップした山を前後から曲線（3次補間等）で作り直す | ◎ 本物の修復。デクリックとデクリップがこれ |
| 帯域拡張（＝音声の超解像） | 無い高音を「ある音から予測して生成」する。軽い方式＝エキサイター（高域を歪ませて倍音を作る、遅延0）、重い方式＝AIモデル（もっともらしい高音を生成） | ◎ 「空気感・クリアさ」はこれで作れる |
| 単なるアップサンプリング補間 | サンプルとサンプルの間を埋めるだけ（44.1k→48k変換等） | × 音は良くならない。情報は増えない |

つまり欲しいのは1と2。2のAI版が本命の「補間」だが、遅延と重さが跳ねる。

## 正直な限界
- マイクが拾ってない情報は、AIでも「それらしく作る」ことしかできない。通話相手に区別がつきにくいレベルは狙えるが、録音を良いマイクと聴き比べれば差は残る
- 自己ノイズが声と同じくらい大きい個体、激しく割れた音、部屋の反響が強い環境は、処理で救える幅に限界がある
- マイクとの距離と置き方（口元に近い・正面）は処理より効く。ここはアプリ側ではどうにもならない

## ボーカル録音での利用（2026-11-08 たくみさん発案）
良さそうだが、通話チューニングのまま歌うと壊れる所があるので **ボーカル用プリセットを別に持つ**。

| 項目 | 通話（既定） | ボーカル |
|---|---|---|
| ゲート／エキスパンダー | 強めでOK | 弱める／オフ寄り（小さい声、息、余韻を切らない） |
| マルチバンド・エキスパンダー | ノイズ優先 | 穏やか（歌のダイナミクスを残す） |
| コンプ | 強め（音量を揃える） | 弱め 2:1級、遅め（抑揚を潰さない） |
| EQ | 明瞭さ優先 | 明瞭さ＋高音の空気感を少し多め |
| リップ除去／ディエッサー | あり | あり（歌でも効く） |
| リバーブ等 | なし | 録る時はなし（ドライ）。後がけが正解 |

録音の鉄則：**処理済みだけを録ると後で直せない**。VSTをDAWに入れて非破壊で使うか、ドライ（生）も同時録音できる形が安全。
モニター（オケに合わせて歌う）用途では低遅延設計がそのまま効く。経路は VB-CABLE ではなく DAW／直接モニターが前提。

## モード制（軽量・低遅延との両立策）
| モード | 中身 | アプリ分遅延目安 | 想定用途 |
|---|---|---|---|
| 低遅延 | DSP一式＋エキサイター式帯域拡張（AIなし） | 約5ms | ゲーム・通話（今の設計） |
| バランス | ＋RNNoise（喋ってる間のノイズも消す） | 約15ms前後 | 普段のDiscord |
| 高音質 | ＋AI帯域拡張／AIノイズ除去（ONNXのモデル実行） | 約30〜50ms、メモリも数百MB級になりうる | 配信・録音 |

「最軽量・最速」と「AIで作る高音質」は同居しないので、切り替えで選べる形が落とし所。

## バランス点＝既定チューニング（2026-11-08 本人の希望「最低遅延・最高音質・最高品質のバランス」）

3つ全部を最大にはできないので、「遅延が増えない音質向上は全部やる、増えるものは最小の1個だけ許す」が設計原則。

**タダで音が良くなるもの（遅延0、全部入れる）**
- 自動キャリブレーションEQ（解析はセットアップ時だけ。リアルタイム負荷ゼロで個体差を消す）
- 内部処理は 32bit float 統一（量子化ノイズの蓄積なし、今のCPUでは負荷差なし）
- ゲイン設計の最適化（クリップさせず、ノイズフロアから遠ざける）
- マルチバンド・エキスパンダー 4バンド（帯域ごとにゲート、発話中も定常ノイズを穏やかに削る、遅延0）
- エキサイター式帯域拡張＋低音の倍音付加（量は控えめ。盛りすぎると安っぽく逆戻りする）
- 非線形段（エキサイター等）だけ 2倍オーバーサンプリング（折り返し歪み防止、追加遅延は1ms未満が目標）

**許す遅延は1個だけ**
- リップノイズ除去の見越し 128サンプル＝2.7ms。これ以外は見越し・FFTを持たない

**バランス点の数値目標（Windows実機で要検証）**
| 項目 | 目標 |
|---|---|
| アプリ分遅延 | 約6ms以下（バッファ64×入出力＋見越し2.7ms） |
| CPU | 1コアの1%未満 |
| メモリ | 15MB以下 |
| 無音時のノイズ | ゲートで体感ほぼ無音 |
| 発話中の定常ノイズ | 実環境で 6〜12dB 減（アーティファクトが出ない範囲） |
| バッファ | 64サンプル固定寄り（32は途切れリスクで品質が落ちる、128は遅延が勝つ。その間の64がスイートスポット） |

**決定（2026-11-08）：既定は「低遅延」モード（AIなし）。** バランス／高音質は後から手動で切り替える追加モードとして残す。
既定モードの帰結：喋ってる最中の定常ノイズ除去はゲート＋HPF＋ノッチ止まりになる（RNNoiseを入れないため）。帯域拡張はエキサイター式（倍音生成、遅延0）で行う。
