# 仮想ケーブルの同梱（2026-11-08 調査）

**決定（2026-11-08）：同梱は見送り。** たくみさんの判断。仮想ケーブルが必要な場合は本人が別途入れる前提で、クライアントは既存デバイスを選ぶだけにする。以下は調査記録として残す。

「同梱」には2通りある。結論が違うので分ける。

## A. VB-CABLE をうちのインストーラに入れる → 可能（条件付き）
- ドライバは Microsoft 署名済みなので、そのまま動く。開発ゼロ
- VB-Audio の配布ルールは「製品だと識別できて、寄付の機会が残る」形なら同梱を認める方向（Voicemeeter については公式 Licensing ページに明記 https://vb-audio.com/Services/licensing.htm ）
- VB-CABLE 本体についても同種の条件とされるが、**配布前に公式条件を再確認する**こと。追加ケーブル A+B / C+D は同梱対象外とされる
- 管理者権限＋再起動が1回要る（ドライバなので避けられない）
- 欠点：遅延は VB-CABLE 側のバッファ依存で、こちらで詰められない（約5〜20msの見込み）
- 自分用だけなら配布ライセンスの心配はほぼなく、実質「自動で入れてくれる」化ができる

## B. 自作の仮想オーディオドライバを同梱 → 技術的には可能、ただし署名の壁
- 中身は作れる：Microsoft の SYSVAD サンプルが土台。リングバッファを小さく（64サンプル級）設計すれば、ケーブル経由の追加遅延を約1〜3msまで詰められる見込み。デバイス名も「MicFilter Mic」にできる
- **壁はコードではなく署名**：Windows 10 1607以降/11 は、Microsoft の署名がないカーネルドライバを読み込まない
  - 正規ルート：EVコード署名証明書（年 数万円〜＋ハードウェアトークン）＋ Microsoft Partner Center で Attestation 署名。WHQL/HLK は Windows Update 配布用なので通常インストールには不要
  - 抜け道：テスト署名モード（bcdedit testsigning on）なら自前署名で動くが、デスクトップに透かしが出る＋一部のアンチチート（ゲーム）がテストモード/署名緩和を嫌って起動しないことがある。ゲームPCには非推奨
- 失敗するとブルースクリーン級のリスクもある（カーネルで動くため）

## C. ドライバ無しで済ませる → 仮想マイク用途では不可
- 「他のアプリからマイクとして見えるデバイス」を作るには、方式が APO でも結局ドライバパッケージ＋署名が要る。ユーザーモードAPIだけでは作れない

## 推奨
1. v1 は A（VB-CABLE をインストーラから自動セットアップ、未導入なら検出して案内）。遅延の主戦場は WASAPI 側で、ケーブル分は許容する
2. 自作ドライバ B は「遅延を本気で詰めるフェーズ2」。やるなら署名コストを払うのが前提で、テストモード運用はしない
