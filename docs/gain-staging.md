# ゲイン設計（音量の作り方、2026-11-08 たくみさん案を採用＋補正）

案：Windowsのマイクレベルは 50 くらいで設定しておいて、アプリ側で綺麗にしつつ音量を丁度良くする。
→ 方向は正解。ただし「50」は固定値ではなく **出発点** にする。理由は下記。

## なぜ固定50ではダメか
- Windowsのレベル表示はデバイスごとに実ゲインが違う（同じ50でもマイクが変われば音量が全然違う）
- アプリ側のデジタルゲインでは直せないものが2つある：
  - **入り口で割れた音**：Windowsレベルが高すぎてADCでクリップした音は、アプリに届く前に壊れている（デクリップで軽症は直せるが完全には戻らない）
  - **ヒスとの比（SNR）**：レベルが低すぎると、アプリで持ち上げてもヒスも一緒に上がる。比は入り口でしか決まらない
- つまり入り口レベルの仕事は「割れない範囲で、なるべく大きく録る」こと

## 正しい決め方（メーター基準）
1. Windowsレベルは **50 を初期値** に置く（たくみさん案）
2. 一番大きな声（歌ならサビ、通話なら大笑い）で **ピークが -12〜-6dB** に入るよう微調整。0dBに触れたら下げる
3. マイクブーストがある機種は **0／オフ固定**（ヒスと歪みの元）
4. その先はアプリ側：コンプで揃え → リミッター天井 -1dB → 出力ゲインで最終調整
   - 目標：通常の声で RMS 約 -18dBFS 前後、ピーク -3dB 以内、最終天井 -1dB

## セットアップの手順（2026-11-08 たくみさん案：まず全フィルターOFFで音量、後から機能）

これが正しい順番。理由：コンプやリミッターが付いた状態で音量を合わせると、本当は割れてるのに見えなくなる（リミッターが隠す）。ゲートが付いてるとノイズフロアも測れない。

アプリのセットアップモード（ウィザード）はこの順で案内する：
0. **全フィルターOFF（ドライ）** で開始
1. Windowsレベル（初期値50）＋アプリ入力ゲインで、一番大きな声のピークが -12〜-6dB、0dBに触れないことを確認 ← ここが音量設定の本体。**このステップは自動化できる（下記「ステップ1の自動化」）。ユーザーの仕事は案内に従って声を出すだけ**
2. 無音を数秒測る（ノイズフロア）。ゲート閾値はここから自動で決める（フロア＋余裕分）
3. フィルターを1つずつON：ハイパス／ノッチ → ゲート → EQ較正 → リップ除去／ディエッサー → マルチバンド → コンプ
4. 最後にリミッター天井 -1dB を入れて、出力ピークと聞こえの音量を再確認（コンプ分で音量感が変わるため）

## ステップ1の自動化（較正ウィザード、2026-11-08 本人の質問で仕様化）
できる。仕組み：
- Windowsマイクレベルはアプリから変更できる（Core Audio の IAudioEndpointVolume）。スライダを人が動かす代わりに、プログラムが「測る→ずらす→測り直す」を回せる
- 割り振りの原則：**まずWindowsレベル（入り口）で合わせ、足りない分だけアプリのデジタルゲインで足す**
  - クリップ検出（0dB張り付き／平らな天井が連続）→ Windowsレベルを下げる。デジタル側では直せないため最優先
  - ピークが低すぎる（例 -24dB未満）→ Windowsレベルを上げる（上限の目安90。それでも足りなければデジタルで補う）
  - 目標：最大声のピーク -9dB（範囲 -12〜-6 の中央）。誤差分を dB で計算して 2〜3 回の反復で収束させる
- 自動化できない部分（正直な限界）：
  - 「一番大きな声」のサンプル自体はユーザーに出してもらう必要がある（歌ならサビの大声）。出してもらった声が実際の最大より小さいと、その分余裕は減る
  - 本体に物理ゲインツマミがあるマイクはアプリから回せない → 検出して「本体ツマミを上げて」と案内する
  - 使用中に常時自動で追う（AGC）は別物。無音でゲインが上がってヒスを持ち上げる副作用があるため、既定にはしない。較正時の自動化が正解

## ながら較正（パッシブ較正、2026-11-08 本人の希望「測定の時間を取るのが嫌」への回答）
専用の測定時間を取らず、普通に使いながら裏で収束させる方式。コツは「上げる」と「下げる」を非対称に扱うこと：
- **下げる（クリップ対策）は証拠が確実**：クリップ検出＝今まさに割れている、という事実。サンプルを待つ必要がないので常時ガード可能。検出したら即 -3dB（反復可、0.5秒間隔）。速い・確実・副作用なし
- **上げるは証拠が不確実**：「今までの最大」が本当の最大とは限らない。だから声の区間だけの統計（上位パーセンタイル）で判定し、ゆっくり・小さく（+1〜2dBずつ、10〜20秒に1回まで）、目標も控えめ（-12寄り）、不感帯（-14〜-6）内では動かない。静かな区間では一切判定しない＝ヒス持ち上げ問題は構造的に起きない
- 統計：音声アクティブ区間の短期RMS蓄積とピークのパーセンタイル。ノイズフロア推定で声/無音を分ける
- 正直な限界：本当の最大声が来る前に「正解」は出せない。初回の大声の最初の音節だけクリップし得る（ガードが数百msで追いつく）。歌など最大値が大事な用途は明示較正ボタン（従来方式、残す）が向く
- 調整の実行先は較正ボタンと同じ EndpointVolume の dB API。全アクションをログに残す

## アプリ側に持たせる機能
- セットアップ時の **自動ゲイン較正**：無音（ノイズフロア測定）→ 普通の声 → 大きな声、の3つを測って入力ゲインを自動設定。割れ／小さすぎを検出したら「Windowsレベルを上げて／下げて」と案内する
- クライアントに **Windowsマイクレベル自体のスライダ** を持たせることも可能（Core Audio の EndpointVolume で録音デバイスのレベルはアプリから変更できる）。初期値50で出す
