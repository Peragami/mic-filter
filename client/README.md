# MicFilter 専用クライアント（Windows）

マイク入力 → `MicFilter.vst3`（ホストして読み込む）→ 選択した出力デバイス、
をやる小さな Win32 アプリ。フレームワーク・ランタイム無し、C++17 + Windows API のみ。

- 音声: WASAPI イベント駆動（`AUDCLNT_STREAMFLAGS_EVENTCALLBACK`、ポーリングなし）
- モード優先順位: **WASAPI排他 → IAudioClient3 低遅延共有 → 通常共有**
  （`../Source/ClientConfig.h` の決定通り。実際に使われたモードは画面下部に表示）
- 48kHz / float32 に統一（共有モードは WASAPI の自動変換に任せる）
- バッファ: 32 / 64 / 128 / 256 サンプル、既定 64。XRUN が続くと自動で一段上げて再起動する

## ビルド（VS2022）

前提: Visual Studio 2022「C++ によるデスクトップ開発」と VST3 SDK。
SDK は `vst3/` の作業ラインが取得したものを使う（このフォルダには同梱しない）。

```powershell
cd mic-filter\client
cmake -B build -A x64 -DVST3_SDK_PATH=C:\path\to\vst3sdk
cmake --build build --config Release
# -> build\Release\MicFilterClient.exe
```

`VST3_SDK_PATH` 未指定なら `..\vst3\vst3sdk` などを自動で探す。
SDK が見つからない構成でもビルドは通るが、その場合 VST3 ホストはスタブになり、
開始時に「SDK 未設定」エラーになる（本番ビルドでは必ず SDK を指定すること）。
SDK から取り込むのはヘッダと `pluginterfaces/base/` の IID 定義4ファイルのみ
（詳細は `thirdparty/README.md`）。

mingw-w64 でのクロスビルドも確認済み（下記「コンパイル確認の範囲」参照）。

## 使い方

1. 起動する。入力／出力デバイスは **ドロップダウンで選択**（MMDevice API で列挙）。
   USB マイクの抜き差し等は `IMMNotificationClient` で検知して一覧をその場で更新し、
   選択中だったデバイスは ID で保持する。
2. **Windows マイクレベル** スライダ: 選択中の録音デバイス自体のレベルを
   `IAudioEndpointVolume` で直接操作する（ドラッグで即時反映、システム全体に効く）。
   - 起動時の表示は **50**（`../docs/gain-staging.md` の初期値）。
     デバイスを選び直すと、そのデバイスの実際の現在レベルを表示する。
   - 決め方: まず 50 から始め、一番大きな声でレベルメーターのピークが
     -12〜-6dB に入るよう調整。マイクブーストがある機種はオフ固定が推奨。
   - 動作中も変更できる（ゲイン調整用にあえて無効化していない）。
3. プラグイン欄で `MicFilter.vst3` を指定（バンドルフォルダのままでよい。
   中の `Contents\x86_64-win\*.vst3` を自動で解決する）。
4. バッファを選んで「開始」。ステータス欄に実モード／往復遅延の目安／XRUN 数が出る。
5. 音質モードは仕様通り「低遅延（AIなし）」固定表示（切替 UI は v0.1 では無い）。

### VB-CABLE へ出して Discord 等で使う場合

仮想ケーブルの同梱はしない決定（`../docs/virtual-cable.md`）なので、別途入れておく。

1. VB-CABLE をインストール（要再起動）
2. このクライアントの出力デバイスで **CABLE Input** を選んで開始
3. Discord 側の入力デバイスで **CABLE Output** を選ぶ
4. Discord 側のノイズ抑制・エコー除去は二重処理になるので切るのが無難

## 自動補正（ながら較正、v0.9〜）
Windowsマイクレベルの自動設定は **VST側ではなくクライアント側** の仕事（VSTは音の流れしか知らず、デバイスを知らない）。v0.9からは専用の測定時間を持たない「ながら較正」方式（docs/gain-staging.md）：「自動補正」チェック（既定ON）を入れて普通に喋っているだけで、音割れを検出したら即 -3dB、声が小さめなら +1.5dB（15秒に1回まで）を Windows 側レベルへ dB 単位で反映する（IAudioEndpointVolume の dB API）。判定ロジックは `src/passive_gain.h`、実行は `src/passive_calibration.cpp`。従来の「自動較正」ボタン（3秒測定方式）は本人の指示で廃止。マイクレベルスライダ（初期値50）も同じ画面にある。

## 既知の制限（v0.1）

- **Windows 実機での動作は未確認**。mingw-w64 + 実 SDK でコンパイル／リンクが通る
  ところまでが確認範囲で、WASAPI 排他の交渉・IAudioClient3 の実周期・実プラグインの
  ロードは Windows 11 実機での確認が要る（下記）。
- プラグインのパラメーター編集は「ON/OFFスイッチのみ」実装済み（2026-11-08追加）：
  各フィルターのチェックボックス＋「ドライ（全OFF）」切替。動作中に切り替えると
  次の音声ブロックから反映される。つまみ（閾値や量）の編集 UI は未実装。
- `ProcessContext`（テンポ／拍子情報）は渡していない。テンポ同期系エフェクトは対象外。
- 通常共有モードまで落ちた場合、受け渡しチャンクは選択バッファではなく
  デバイス周期（既定約10ms）になる。バッファ選択が効くのは排他と IAudioClient3 時。
- 使用中のデバイスが抜かれた場合の自動復旧は無い。エンジンは止まるので、
  一覧から選び直して開始し直すこと。
- 入力はステレオ化してプラグインに渡す（モノラルマイクは複製）。出力がモノラル
  デバイスの場合はダウンミックスする。
- バンドル解決は `x86_64-win` のみ（Windows on ARM のバンドルは未対応）。

## コンパイル確認の範囲（2026-11-08, Linux VM 上）

- mingw-w64 (g++ 13) + 実 VST3 SDK（`../vst3/vst3sdk`）:
  **全ソースのコンパイル＋リンク成功**、`MicFilterClient.exe`（PE32+ GUI, x86-64）生成。
  VST3 ホストはスタブではなく実コードでビルドされている。
- SDK なし構成: スタブホストでコンパイル＋リンク成功も確認。
- 未確認: VS2022 (MSVC) でのビルド、Windows 実機での実行全般。
  MSVC 固有の差異が出るとすれば `/utf-8` 前提の日本語リテラルと
  `swprintf_s` 等の CRT 関数のみで、コード側は標準範囲に収めてある。
